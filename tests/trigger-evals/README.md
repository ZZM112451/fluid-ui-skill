# 触发评测

[20 条正反例](cases.json) 覆盖四风格、三强度、现有系统、四平台、无动画和无关任务。环境与日期 2026-11-04，Codex CLI 0.164.0 / Windows。

判定方式：真实自动触发必须从独立 Agent 日志观察主动读取/激活 fluid-ui；显式调用从 `$fluid-ui` 请求与实际读取判断；只比较描述、正则或文件存在为静态推断。

当前 20 条预期已作静态描述审查：范围与边界一致。**20 条均未进行逐条自动触发实测，不记录为 20/20 通过。** 实际显式调用是另一个独立任务，见 [调用证据](../../docs/verification/codex-invocation.txt) 和 [报告](../../docs/verification/report.md)。

另执行了一个不包含 Skill 名称的独立自动选择样本：Agent 主动读取并使用 fluid-ui，见 [自动调用证据](../../docs/verification/implicit-invocation.txt)。不能把这个样本外推为 20 条全部通过。案例 18 的纯格式整理通常不需要完整设计 Skill，若误触发应收窄描述，不扩大 UI 修改范围。

复现建议：每条使用独立空项目和相同模型配置，保存 JSONL，观察具体技能读取事件、任务结果和是否修改无关文件。不要在同一个已加载 Skill 的会话中连续判定全部正反例，避免上下文污染。
